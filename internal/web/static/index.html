Case details

With a conversation id, every expectation is judged on the calls that declared it and on nothing else. An absent id, a claim that needs absence, or a recording-level invariant stays INCONCLUSIVE rather than concluding from part of the evidence.

Complete-boundary mode: a missing tool call in a verified, completed recording can fail an existence check or satisfy a zero-count check. Missing results still cannot prove result-text absence. Incomplete recordings are inconclusive.

Review the saved case definition
Saving puts the case beside your recordings, where the Regression lab and tapelog lab run both find it. An existing case is never replaced without reading it first.
Advanced: legacy YAML test export
Sequence checks an ordered subsequence of answered tool names. The order below is the requirement; changing it may make this cassette fail. Zero attempts checks this boundary only and will fail against a cassette containing the selected attempt. A recorded error can be asserted absent: the generated rule inspects recorded results only, so a denied or unanswered call neither proves nor breaks the absence, and the new test fails against the recording that motivated it because it states the behaviour you want next time.
Save beside the recording, or change this path. Assertions apply to the tool across the cassette, not a single request ID.
Legacy assertions use their original semantics: missing results do not prove an error was absent. The case builder above uses explicit eligibility checks.
