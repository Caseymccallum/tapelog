# Tapelog v0.5.0-beta.1

**The first public beta of the redesigned workbench.** Tapelog records every MCP tool call that
crosses it into a hash-chained log, can deny calls by policy *before* anything executes, replays a
recording as a hermetic server, and runs regression cases over recorded evidence.

It is local-first: no account, no server, no automatic network call, and nothing is sent anywhere.

## What is new in this beta

- **A redesigned workspace** (Project Prism): one typographic and spacing system across the
  recording library, session overview, event inspector, conversation investigation, recording
  comparison, Behaviour Intelligence, the Regression Lab and the policy studio. Layouts use
  whitespace and separators instead of nested bordered boxes, and every screen reflows from
  1920px down to 320px.
- **Conversation investigation** — one MCP connection can serve many agent conversations. The
  behaviour view groups activity by the client-declared conversation id, leads each group with
  that id, keeps the unattributed remainder visible and separate, and opens a per-conversation
  timeline. Attribution is a claim, never a session boundary.
- **A saved-suite editor that reads like the rest of the product** — claim, plain-language
  description and evidence per row; `Save changes` separated from `Run saved suite`; the run action
  disabled while the draft differs; unsaved edits survive navigation; the equivalent CLI command
  sits in its own block with a Copy action.
- **Evidence verdicts kept apart** — chain integrity, structure, completeness and eligibility are
  four different questions, and the UI and CLI name which one decided a claim. A recording with an
  intact chain but an invalid structure now says so in the session's trust panel.
- **Behaviour summary** that states what it counted (recordings, calls, results, errors, denials,
  unanswered) and what it could not decide.

## Supported platforms

**Windows amd64** and **Linux amd64** — both were built, executed and walked through for this
release. macOS and linux/arm64 compile from source but were not executed, so **no archive is
published for them and no support is claimed**. Other platforms: build from source, best effort.

## Install

1. Download the archive for your platform and the `checksums.txt` file.
2. Verify the download:

   ```bash
   # Linux
   sha256sum -c checksums.txt
   # Windows PowerShell
   Get-FileHash .\tapelog_0.5.0-beta.1_windows_amd64.zip -Algorithm SHA256
   ```

   The published `checksums.txt` carries the exact hashes; verify the signature over it first:

   ```bash
   cosign verify-blob \
     --certificate checksums.txt.pem \
     --signature checksums.txt.sig \
     --certificate-identity-regexp "https://github.com/Caseymccallum/tapelog/.github/workflows/release.yml@.*" \
     --certificate-oidc-issuer https://token.actions.githubusercontent.com \
     checksums.txt
   ```

3. Extract the **whole** archive — the guides, the rest of `docs/`, and the fictional demo travel
   with the binary, so every link in them resolves on your machine.

   ```bash
   unzip tapelog_0.5.0-beta.1_windows_amd64.zip
   tar -xzf tapelog_0.5.0-beta.1_linux_amd64.tar.gz
   ```

   On Linux, if your extraction tool dropped the executable bit: `chmod +x tapelog`.

4. Check what you have:

   ```bash
   tapelog version      # prints the version and the commit
   tapelog --help
   ```

5. First run, needs nothing but the binary (no agent, account or network):

   ```bash
   tapelog demo --dir demo-run
   tapelog web --dir demo-run/recordings
   ```

   `demo` records a fictional session through the real boundary — an allowed call, a policy-denied
   call and a tool error — verifies the chain it just wrote, and prints the next three commands.

6. The bundled Regression Lab suite deliberately contains a FAIL and an INCONCLUSIVE:

   ```bash
   tapelog lab suite --dir examples/regression-demo --suite demo-suite.json
   # FAIL · 2 pass, 1 fail, 2 inconclusive — exit code 1 by design
   ```

The full walkthrough, including putting the boundary in front of your own MCP server, is in
`docs/GETTING_STARTED.md` inside the archive.

## What Tapelog can and cannot prove

Say this before quoting any result:

- It sees **only traffic crossing its boundary**. An agent's built-in tools never appear, so a clean
  recording is not evidence of clean behaviour.
- A verified chain proves the bytes were not altered. It does not prove who wrote them, when, or
  that the session is complete. Those are separate verdicts, and the product reports them separately.
- Conversation attribution is declared by the client (`_meta`), not authenticated. It is a claim.
- Redaction is bounded: secret-shaped keys are masked in **arguments and in JSON result bodies**
  (parsed and re-serialised, depth- and size-limited), and credential patterns are masked anywhere.
  A secret that arrives as free text under an innocuous key can still survive. Treat every recording
  as secret material; the beta is for fictional or disposable data.

## Known limitations

- **Directory review mode has no live approvals.** `tapelog web --dir <recordings>` is read-only over
  a directory; it does not connect to a running boundary, so pending `confirm` decisions are not
  actionable there.
- **Limits are enforced, not tuned.** The workspace reads up to 16 MiB / 50,000 events per recording;
  larger files are refused with the documented limit rather than half-read.
- **One connection, many conversations.** A long-lived harness can keep one MCP connection across
  several conversations; conversation ids group activity inside a session, they never split it.
- **Signing is CI-only.** These archives are built by the release workflow from this tag: `checksums.txt`
  is signed with cosign (keyless, GitHub OIDC), each archive has an SBOM, and the artifacts carry a
  build-provenance attestation. `MANIFEST.txt` inside the archive records the commit and says the
  signing was performed by the release workflow.
- **Policy Studio never writes the active policy.** It reads the policy in use and previews
  candidates; saving a candidate is a browser download into a new file, not a server-side write.
- No telemetry, no crash reporting, no update check — Tapelog makes no network call on its own.
  Two commands can reach the network, and only when you run them: `tapelog checkpoint` submits the
  checkpoint's chain head to a public transparency log (**Rekor is the default**; pass
  `--witness none` to keep it local), and `tapelog export otel <session.jsonl> --endpoint <url>`
  sends OTLP traces to the endpoint you name (with no endpoint it prints to stdout).

## Feedback

Beta feedback is genuinely wanted and always voluntary.

- Bug, installation problem, MCP client/server compatibility, UX feedback and feature requests have
  their own issue templates in the repository.
- Please include: operating system, `tapelog version`, MCP client and server, reproduction steps and
  sanitised diagnostics.
- **Never paste credentials, tokens or a recording of real work.** Use `tapelog demo` output or a
  recording made against disposable data.
- Security reports: use the private channel in `SECURITY.md`, not a public issue.
